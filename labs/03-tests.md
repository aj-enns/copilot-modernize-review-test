# Lab 3 - Generate a test framework and tests (45 minutes)

**Start:** .NET 10 app in `starter/BookingLab`; **no tests** under `starter` yet.
**Finish:** your own xUnit project and Playwright suite with visible outcomes.
Try generating your own tests first. If you get stuck, preserve your attempt,
then use `reference/tests` or `reference/e2e` for help. Explicitly ask Copilot to
read a reference if you want it explained. Keep the repository root open.

## 1. Instructions-first unit tests (15 minutes)

Choose either option with built-in **Agent** and repository instructions active:

- **Copilot:** paste the prompt below.
- **Local:** run `/quote-tests`, or paste the prompt below.

To switch, click **New Chat (+)** at the top of Chat, then choose
**Session Target > Copilot** or **Local** before sending your first message.
Existing chats cannot switch. If **Local** is unavailable, use **Copilot**.
The custom **Test coach** agent is used in section 2.

```text
Read starter/BookingLab/QuoteCalculator.cs and our business contract, not reference
solutions. Create an xUnit test project at starter/tests/BookingLab.Tests targeting
.NET 10 and reference the application project. Use Microsoft.NET.Test.Sdk,
xunit, and the Visual Studio xUnit runner with compatible pinned versions.
Use theory data for 1 and 30 nights, 1 and 6 guests, 6 versus 7 nights, and
invalid values below and above both ranges. Assert exact decimal totals and
exception parameter names. Calculate expected totals independently; do not
call production code to produce the expected values. Run the tests and
report actual results. Do not change production behavior.
```

Inspect the generated project reference and ensure it targets **your app**,
not `reference`. Example known-compatible package versions are Test SDK
17.14.1, xunit 2.9.3, and runner 3.1.4. If the agent uses newer versions, check
compatibility before accepting. It should not add a database or mocking package
to test this pure calculator.

In a new terminal at repository root (assuming you are root folder):

```text
cd .\starter\
dotnet test tests/BookingLab.Tests
```

Expected independently computed totals: 1/1 = 110, 6/2 = 720, 7/2 = 756,
30/6 = 4320. Reject tests that assert only "not null" or reproduce the
implementation formula instead of checking these values.
Temporarily change `>= 7` to `> 7` in **your attendee app**, run tests, observe
a failure, then restore **only that edit** in the editor and rerun. Do not use
Git reset or discard unrelated changes.

## 2. Custom-agent browser tests (20 minutes)

Select **Test coach** in the agent picker and paste the browser-test prompt below.
Read
`.github/agents/test-coach.agent.md` to see the named role and bounded behavior.
It has no hardcoded model or brittle tool IDs; normal permissions still apply.
Unlike auto-applied instructions, this role must be selected.

```text
Create a Node Playwright Test framework in starter/e2e for starter/BookingLab.
Pin @playwright/test, create a package-lock.json, and add an npm test script.
Use Chromium, baseURL http://127.0.0.1:5180, and a managed webServer command
that runs ../BookingLab with --no-launch-profile and --urls on that address.
Set reuseExistingServer false and use /health as readiness URL.
Test the form using accessible labels and roles: 7 nights/2 guests shows
Total: $756.00, changing to 6 nights shows $720.00. Test API HTTP 400 for
invalid nights and guests, and a visible UI server-error or network-error
path. Clear stale totals on failure. Do not inspect reference solutions,
use arbitrary sleeps, change production behavior, add MCP, or depend on a
manually started server. Install Chromium if needed, run tests, and report
the commands and actual results.
```

Stop your manual app server with Ctrl+C **before** this command. In a new terminal
at repository root, the same commands work in PowerShell and bash:

```text
cd starter/e2e
npm ci
npx playwright install chromium
npm test
```

On first scaffolding there must already be a lockfile generated by `npm install`
before `npm ci` can work. Linux prerequisites are in [setup](../docs/setup.md).
The managed server should start, return health, execute tests, then stop. A port
collision should fail instead of silently testing an unrelated server.

Browser min/max constraints do not prove server validation: send invalid inputs
directly through Playwright's request fixture too. For a visible server error,
remove the input's `min` in that test only, or intercept the response. Assert
the error text and absence of a stale successful quote.

## 3. Compare approaches and evidence (10 minutes)

Use a fresh chat with built-in Agent and repeat just one test-generation task,
without selecting Test coach. Keep the same source and instruction context.
Compare scope discipline, test matrix, locators, commands, and whether failures
are reported. Do not infer guaranteed quality from one model response.

The distinction: instructions supply shared constraints; prompt files supply
reusable tasks; a custom agent supplies an explicitly selected role and scope.
They can work together. Neither an agent name nor an instruction file runs tests
on its own.

**Exit check:** show a real failing-then-passing threshold test and a passing
browser flow. Inspect diffs for accidentally weakened app behavior.
If scaffolding stalls, preserve your files and demonstrate the verified
reference from repository root:

```powershell
dotnet test .\reference\tests\BookingLab.Tests
Set-Location .\reference\e2e
npm ci
npx playwright install chromium
npm test
```

```bash
dotnet test reference/tests/BookingLab.Tests
cd reference/e2e
npm ci
npx playwright install chromium
npm test
```

Reference paths are relative to the repository root. The reference server tests
.NET 10, not a partially upgraded app.
